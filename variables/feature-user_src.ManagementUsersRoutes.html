  • ReadonlyCREATE_USER: "/management/users"
    • HTTP method: POST

    Creates a new user account.

    Request body: CreateByEmailRequest. Response body: UserPrivatePayload.

    Authorization:

    • Public Access: Denied.
    • Allowed Roles: STAFF, ADMIN (OR semantics).
    • Allowed Account Statuses: ACTIVE (OR semantics).
    • Required Permissions: USER_CREATE_AS_USER for USER target; USER_CREATE_AS_STAFF for STAFF target (AND semantics).
    • Authority Level: Actor cannot create a user with an authority level equal to or greater than their own.

    Security: Sensitive administrative operation. Requires mandatory MFA setup on the manager's account; returns TOTP_NOT_ENABLED if TOTP is not configured. When enabled, MFA Step-up is required via MFA_CONFIRMATION_REQUIRED. Session must be verified via REAUTHENTICATE_SESSION if stale.

    Audit logging: Persist an AuditEventPrivate for successful execution and all failed attempts.

    • Action: MANAGEMENT_CREATE_USER.
    • Actor: USER. Set actorId to the administrator performing the operation.
    • Resource: USER. Set resourceId to the new account id.
    • Metadata: Include:
    1. ClientInfo (see CommonAuditMetadataKey).
    2. EMAIL_ADDRESS — the email used for creation.

  • ReadonlyGET_USERS: "/management/users"
    • HTTP method: GET

    Returns a paged list of summary users based on filters.

    Pagination & sort (names from ListingParamNames):

    • PAGE_NUMBER — one-based page index (1 is the first page).

    • PAGE_SIZE — page size.

    • SORT_BY — exactly one of:

    • AUTHORITY_LEVEL

    • LAST_LOGIN_AT

    • LAST_ACTIVE_AT

    • SCHEDULED_PERMANENT_DELETION_AT

    • TEMPORARY_LOCKOUT_UNTIL

    • NICKNAME

    • DISPLAY_NAME

    • BIRTHDATE

    • CREATED_AT

    • UPDATED_AT

    • SORT_ORDER — exactly one of:

    • ASC

    • DESC

    • Filters (UserFilterValues): all filters are optional. Multi-value filters use repeated query keys with OR semantics; different keys combine as AND.

    • Multi-value Include Filters (repeated query keys, OR semantics):

    • USER_ID — filter by one or more specific user IDs.

    • ROLE — filter by one or more UserRole serial names.

    • ACCOUNT_STATUS — filter by one or more UserAccountStatus serial names.

    • ACCOUNT_STATUS_ON_RESTORE — filter by target UserAccountStatus serial names.

    • PERMISSION_CODES — filter by one or more explicit PermissionCode strings.

    • ACCOUNT_LOCKOUT_TYPE — filter by one or more AccountLockoutType serial names.

    • Multi-value Exclude Filters (repeated query keys, NOT IN semantics):

    • EXCLUDE_ROLE — exclude specific UserRole serial names.

    • EXCLUDE_ACCOUNT_STATUS — exclude specific UserAccountStatus serial names.

    • EXCLUDE_ACCOUNT_STATUS_ON_RESTORE — exclude target UserAccountStatus serial names.

    • EXCLUDE_PERMISSION_CODES — exclude specific PermissionCode strings.

    • EXCLUDE_ACCOUNT_LOCKOUT_TYPE — exclude specific AccountLockoutType serial names.

    • Exact Filters:

    • IS_TOTP_ENABLED — boolean flag for TOTP 2FA status.

    • NICKNAME — filter by exact nickname handle.

    • DISPLAY_NAME — filter by exact display name.

    • Presence Filters:

    • IS_ACCOUNT_STATUS_ON_RESTORE_SET — filter by whether target status on restore is set.

    • IS_LAST_LOGIN_AT_SET — filter by whether user has logged in at least once.

    • IS_LAST_ACTIVE_AT_SET — filter by whether user has recorded activity.

    • IS_UPDATED_AT_SET — filter by whether user record has been updated.

    • IS_SCHEDULED_PERMANENT_DELETION_AT_SET — filter by whether deletion is scheduled.

    • IS_TEMPORARY_LOCKOUT_UNTIL_SET — filter by whether temporary lockout is active.

    • IS_STORAGE_QUOTA_BYTES_SET — filter by whether custom storage quota is assigned.

    • IS_STORAGE_MAX_UPLOAD_SIZE_BYTES_SET — filter by whether custom max upload size is assigned.

    • IS_STORAGE_MAX_PENDING_UPLOADS_SET — filter by whether custom max pending uploads count is assigned.

    • IS_STORAGE_CONFIGURATION_SET — filter by whether storage configuration overrides exist.

    • IS_NICKNAME_SET — filter by whether user has a nickname set.

    • IS_DISPLAY_NAME_SET — filter by whether user has a display name set.

    • IS_AVATAR_SET — filter by whether user has an avatar image set.

    • IS_BIRTHDATE_SET — filter by whether user has a birthdate set.

    • Range Bounds (inclusive bounds):

    • AUTHORITY_LEVEL_TO — inclusive upper bound for authority level.

    • TEMPORARY_LOCKOUT_UNTIL_FROM — lower bound temporary lockout expiration timestamp.

    • STORAGE_QUOTA_BYTES_FROM — lower bound custom storage quota in bytes.

    • HTTP method: PATCH

    Updates user details, status, or permissions.

    Path parameter: USER_ID.

    Request body: ManagementUpdateUserRequest. Response body: UserPrivatePayload.

    Authorization:

    • Public Access: Denied.
    • Allowed Roles: STAFF, ADMIN (OR semantics).
    • Allowed Account Statuses: ACTIVE (OR semantics).
    • Required Permissions: Required permissions depend on the fields provided in ManagementUpdateUserRequest and the target user's role (AND semantics for all provided fields):
    • If accountStatus is set: USER_UPDATE_STATUS_FOR_USER (target: USER) USER_UPDATE_STATUS_FOR_STAFF (target: STAFF)
    • If authorityLevel is set: USER_UPDATE_AUTHORITY_FOR_USER (target: USER) USER_UPDATE_AUTHORITY_FOR_STAFF (target: STAFF)
    • If permissionCodes is set: USER_UPDATE_PERMISSIONS_FOR_USER (target: USER) USER_UPDATE_PERMISSIONS_FOR_STAFF (target: STAFF)
    • If lockoutType or temporaryLockoutUntil is set: USER_UPDATE_STATUS_FOR_USER (target: USER) USER_UPDATE_STATUS_FOR_STAFF (target: STAFF)
    • Authority Level: Actor's level must be strictly greater than the target's level. Actor cannot target own account.

    Security: Sensitive administrative operation. Requires mandatory MFA setup on the manager's account; returns TOTP_NOT_ENABLED if TOTP is not configured. When enabled, MFA Step-up is required via MFA_CONFIRMATION_REQUIRED. Session must be verified via REAUTHENTICATE_SESSION if stale.
