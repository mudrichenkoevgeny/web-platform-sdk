## MANDATORY REVIEW CHECKLIST

### 1. TypeScript Style, Type Safety & Error Handling
- **Complete Production Code Only:** NO stubs, placeholder code, dummy components, `TODO` markers, or `// ... rest of code`.
- **NO Trailing Commas** in arguments, parameters, arrays, or objects.
- **NO Agent-Generated Inline Comments (`//`, `/* ... */`) or New `TODO`/`FIXME`:** Logic must be self-documenting. Preserve pre-existing developer `// TODO:` / `// FIXME:` comments unless resolved by the task. **NEVER delete, strip, or omit TSDoc (`/** ... */`).**
- **NO FQN / Deep Relative Paths:** Forbidden to use inline `import('...')` qualifiers or deep relative imports (`../../`) across module boundaries. Use package/workspace imports or configured path aliases (`@/...`).
- **Type-Only Imports:** Use `import type` whenever an imported symbol is used exclusively as a type.
- **Strict Type Safety (`as any` Ban):** Must pass TS `strict` mode with zero implicit `any`. NO `as any`, `as unknown as Record<...>`, or double casting. Use Type Guards (`in`, `typeof`, `instanceof`) or explicit interface inheritance.
- **Strict Enums in State:** NEVER use generic `string` in `ScreenState` for fixed value sets (statuses, roles, lockout types, etc.). Use imported TypeScript enums (`UserRole`, `UserAccountStatus`, `AccountLockoutType`) and `z.enum(...)` schemas; no `Object.values()` string-matching hacks.
- **Branded Domain IDs:** Define IDs as intersection branded types (`string & { readonly __brand: '...' }`). Always convert raw strings via `toXxxIdOrThrow(value)` / `toXxxIdOrNull(value)`. Direct casting (`as UserId`) is strictly forbidden.
- **Control Flow & Naming:**
  - Mandatory `{ ... }` block braces for all `if` statements (NO single-line `if (cond) return`).
  - Exhaustive `switch` or `Record` map for strictly typed state unions without a `default` branch.
  - Domain-focused outcome variable names (`operationResult`, NOT `res` or `data`). Suffix Zod schemas with `Schema`.
- **POJO Error Handling:** NEVER use `throw new Error()` inside Repositories, UseCases, or Adapters. Always return `AppError` subclasses (`code`, `isRetryable`) wrapped in `appResultFailure(...)`. Module `AppErrorParser` implementations must follow Chain of Responsibility with `CommonErrorParser` fallback. Throwing is permitted ONLY in boundary parsers (`toEntityIdOrThrow`) or React context hooks outside their Provider.

### 2. Data Layering, UseCases, DI & Persistence
- **Network DTO vs. Domain Layering:**
  - `FetchApi` classes act strictly as transport clients: execute native `fetch` via `HttpClient` (`HttpClientConfigPlugin` interceptors), validate wire payloads with Zod `*PayloadSchema`, and return `AppResult<*Payload, AppError>`.
  - DTO-to-domain mapping (`snake_case` -> `camelCase` via foundation mappers like `toOpenGlobalSettings`, `toSessionToken`, `toOpenUserConfiguration`) MUST occur strictly in the Repository or UseCase layer.
  - UI components and Zustand stores MUST consume strictly typed domain models and NEVER handle raw DTO payloads directly.
- **UseCases & Params:**
  - UseCases must define only a single `public async execute(...)` method (legacy `invoke` is forbidden).
  - Methods with 3+ optional parameters MUST accept a typed Options Object interface (`GetEntitiesParams`) instead of positional arguments.
- **DI & Domain Parsers:** NEVER hardcode empty default parsers (e.g., `CompositeAuditActionTypeParser([])`) in DI containers. Domain parsers must be required properties in the Config interface and injected from the top-level graph.
- **Persistence:** Sensitive data (e.g., auth tokens) MUST use `EncryptedSettings` (Web Crypto API). Never store or expose raw tokens in plain `localStorage`/`sessionStorage`.

### 3. State Management (Zustand), Pagination & Routing
- **Isolated Per-Instance Screen Stores:** Screen/component stores MUST use vanilla `createStore()` + React Context Provider + `useStore(context, selector)`. Global `create()` singletons are strictly forbidden for screen UI state, form inputs, and step transitions.
- **Lazy Store Initialization:** Providers MUST initialize stores with `useState(() => createMyStore(deps, initialState))`. Using `useRef` (`if (!storeRef.current) ...`) is strictly forbidden.
- **Side-Effects Isolation:** NEVER trigger API calls or data fetching inside store factory functions (`createStore`). Always initiate data loading inside a `useEffect` in the React component or Controller after mount.
- **Pagination State & Selectors:**
  - Initial state before first fetch MUST use `pageNumber: 1` and `totalPages: 0` (or `createInitialPaginationState<T>()`).
  - Use pure selector functions (`getNextPageNumber`, `hasMorePages`, `isPaginationIdle`, `canLoadMorePages`) for derived states.
  - Pass `PagedResult` intact to `appendResultToPaginationState` without destructuring it in the store.
- **Routing & URL as Single Source of Truth:**
  - Host apps (`samples/*`) own TanStack Router (file-based `src/routes/`) and `createRootRouteWithContext<RouterDIContext>()`. SDK screens MUST NOT hardcode router instances or hooks; they receive `searchParams` and navigation callbacks (`onNavigateToX`, `onSearchParamsChanged`) via `dependencies`.
  - Filters, sorting, and pagination live in the URL; screen Zustand stores MUST NOT hold filter/sort state internally.
  - Validate search params via flat Zod schemas (`*ParamsSchema` / `*SearchSchema.ts` with array coercion) using `validateSearch: (rawSearch) => parseSearchParams(*ParamsSchema, rawSearch)` (or `*ParamsParser.parse(rawSearch)`). Use pure converter functions outside components (`searchParamsToListingStates` / `listingStatesToSearchParams`).
  - List/table search param updates MUST use `replace: true` in `navigate(...)`.
  - Format network query strings via `appendQueryParamsToPath(basePath, params)`. Smart back navigation uses `useNavigateUp()`, `PARENT_ROUTE`, `cleanSearchParams()`, and `useEnsureHistoryStack()`.
